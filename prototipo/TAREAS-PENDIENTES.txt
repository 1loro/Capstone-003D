ESTACIONANDO — TAREAS PENDIENTES Y ESTIMACION DE TIEMPO
=========================================================
Generado tras el primer despliegue en vivo (Vercel + Render + Supabase).
Estimaciones en horas de trabajo efectivo, asumiendo que quien lo hace ya
conoce el código (no incluye tiempo de aprendizaje de una tecnologia nueva
la primera vez que se toca). Los rangos reflejan optimista-realista.

Orden recomendado: Epico 1 -> 2 -> 3 -> 4 -> 5a -> 5b(PWA) -> 6, en paralelo
donde se pueda repartir entre las 3 personas.


EPICO 1 — RESEÑAS
-----------------
[ ] createReviewAction: 1 reseña por reserva/autor, rating 1-5,
    comentario opcional (la constraint unica ya existe en la tabla)         2-3 h
[ ] Regla: solo permitir reseñar reservas cuyo endTime ya paso              1 h
[ ] Boton "Calificar" en historial de reservas (ambas direcciones:
    renter->host y host->renter)                                           3-4 h
[ ] Query de rating promedio por usuario + mostrarlo en perfil
    y en tarjetas de espacio                                               2-3 h
[ ] Admin: eliminar una reseña abusiva desde el panel                      1-2 h
                                                          SUBTOTAL EPICO 1: 9-13 h


EPICO 2 — NOTIFICACIONES + EMAIL
---------------------------------
[ ] Elegir y configurar proveedor de email (Resend recomendado,
    se integra directo con Next.js)                                        1 h
[ ] Plantillas de email: reserva confirmada (x2), reserva cancelada,
    recordatorio                                                           3-4 h
[ ] Cron de recordatorio (Vercel Cron + route handler)                     2-3 h
[ ] Crear filas en tabla notifications desde las Server Actions
    existentes + disparar el email correspondiente                        3-4 h
[ ] UI: campanita de notificaciones con no-leidas (mismo patron
    de useRealtimeRefresh que ya existe)                                   4-5 h
                                                          SUBTOTAL EPICO 2: 13-17 h


EPICO 3 — RECUPERAR CONTRASEÑA
--------------------------------
[ ] Modelo de token de reseteo (mismo patron que sesiones: token
    opaco + hash guardado) + migracion                                     1-2 h
[ ] Flujo completo: "Olvide mi contraseña" -> email con link ->
    formulario nueva contraseña -> invalidar sesiones activas              4-6 h
                                                          SUBTOTAL EPICO 3: 5-8 h


EPICO 4 — PAGOS (el mas pesado)
---------------------------------
[ ] Elegir proveedor (Webpay Plus/Transbank recomendado para
    contexto chileno, tiene ambiente sandbox gratis) + setup cuenta        2-3 h
[ ] Integracion checkout: crear Payment en PENDING, redirigir              4-6 h
[ ] Route Handler de retorno/webhook que confirma el pago y
    recien ahi confirma la reserva                                         3-5 h
[ ] Reembolso automatico (politica 90/10) contra API de reembolsos         3-4 h
[ ] Manejo de pago fallido / expirado                                      2-3 h
[ ] Pruebas end-to-end contra el sandbox del proveedor                     3-4 h
                                                          SUBTOTAL EPICO 4: 17-25 h

EPICO 5b — APP MOVIL
-----------------------
Decision pendiente antes de estimar en serio — dos caminos MUY distintos:

  OPCION A) PWA (envolver la web actual) — RECOMENDADO para el tiempo
  que queda de tesis. Reutiliza ~100% del codigo ya construido.
    [ ] manifest.json + iconos + splash screen                             1-2 h
    [ ] Service worker basico (shell offline)                              2-3 h
    [ ] Prompt de "Agregar a inicio" + ajustes de meta tags                1-2 h
                                                    SUBTOTAL OPCION A (PWA): 4-7 h

  OPCION B) Nativa (React Native / Expo) — solo si sobra tiempo
  despues de Pagos y Reseñas. Reutiliza ~0% de la UI.
    [ ] Separar logica de negocio de las Server Actions hacia una
        capa de API REST propia (un cliente nativo no puede llamar
        Server Actions directamente)                                       1-2 semanas
    [ ] Nuevo proyecto Expo + auth contra la nueva API                     3-5 dias
    [ ] Rehacer UI completa: explorar, detalle de espacio, wizard
        de publicacion, reservas, perfil                                   3-5 semanas
    [ ] Mapas nativos (react-native-maps + Mapbox SDK)                     3-5 dias
    [ ] Push notifications (Expo push service)                             1-2 dias
    [ ] Publicacion en tiendas: fuera de alcance realista de un
        semestre — demo via Expo Go alcanza
                                              SUBTOTAL OPCION B (NATIVA): 6-10 semanas

Nota: estas horas asumen que cada persona ya esta familiarizada con el
patron de Server Actions + Prisma + notifyChange usado en todo el proyecto.
La primera vez que alguien integra un proveedor nuevo (Transbank, Resend,
un proveedor de KYC) casi siempre toma mas tiempo que lo estimado por leer
su documentacion y probar el sandbox — dejar margen extra ahi.
