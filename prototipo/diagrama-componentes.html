Lectura rápida del diagrama

  • Un solo punto de entrada al servidor. El navegador solo le habla a Next.js. Ni el servicio Java ni Mapbox ni Supabase Storage son alcanzables directo desde el cliente — todo pasa server-a-server, así ningún token ni credencial queda expuesto en el navegador.
  • Dos caminos hacia Mapbox. Next.js lo llama directo para geocodificar direcciones; el servicio Java lo llama por su cuenta para calcular rutas y tiempos de viaje. Son dos llamadas independientes al mismo proveedor externo, no una relación en cadena.
  • El único canal que no pasa por una petición normal es Realtime. Cuando algo cambia en PostgreSQL, Supabase empuja un aviso directo al navegador por websocket — pero ese aviso nunca lleva datos, solo dice "algo cambió"; el navegador le vuelve a pedir los datos reales a Next.js por el camino de siempre.
  • Las cuatro cajas punteadas son literalmente lo que falta para cerrar el ciclo completo del marketplace: Pagos (dinero real), Email (avisos), KYC (confianza), Reseñas (reputación). Cada una se conecta en el punto exacto donde Next.js ya ejecuta la acción correspondiente — no requieren rediseñar nada de lo que ya existe, solo agregar la llamada.
